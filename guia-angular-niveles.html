TypeScript esencialtipos · interfaces · clases

Angular se escribe en TypeScript: JavaScript con tipos. Lo mínimo para arrancar: tipar variables y funciones, describir objetos con interface y entender clases.

// tipos básicos
let nombre: string = 'Rafa';
let edad: number = 33;
let activo: boolean = true;
let tags: string[] = ['angular', 'ts'];

// un objeto con forma definida
interface Producto {
  id: number;
  nombre: string;
  precio: number;
  stock?: number;          // opcional
}

// funciones tipadas y arrow functions
function total(items: Producto[]): number {
  return items.reduce((acc, p) => acc + p.precio, 0);
}
const esCaro = (p: Producto) => p.precio > 10000;

// clase: la base de todo componente/servicio
class Carrito {
  private items: Producto[] = [];
  agregar(p: Producto) { this.items.push(p); }
  get cantidad() { return this.items.length; }

Reactividad

Signals: estado reactivosignal() · computed()

Una cajita con un valor que avisa cuando cambia; la vista se actualiza sola. Se lee siempre con paréntesis. Analogía: planilla de cálculo, computed es la celda con fórmula.

APIQué hace
x = signal(1)Crea un valor reactivo con escritura.
x()Lee el valor actual.
x.set(5)Reemplaza el valor.
x.update(n => n+1)Nuevo valor a partir del anterior.
t = computed(() => x()*2)Derivado, solo lectura, se recalcula solo.
effect(() => log(x()))Corre cada vez que cambia lo que lee.
import { Component, signal, computed } from '@angular/core';

@Component({
  selector: 'app-carrito-item',
  template: `
    <p>x{{ cantidad() }} = ${{ total() }}</p>
    <button (click)="cantidad.update(n => n + 1)">+</button>
  `,
})
export class CarritoItemComponent {
  precio = signal(3500);
  cantidad = signal(1);
  total = computed(() => this.precio() * this.cantidad());
}

Los datos bajan por inputs; los eventos suben por outputs. El hijo nunca modifica lo que recibe: emite y el padre decide.

@for (p of productos(); track p.id) {

Datos y servicios

Servicios e inyección de dependencias@Injectable · inject()

Un servicio es una clase con lógica compartida (llamadas HTTP, estado). Angular crea una sola instancia y se la da a quien la pida con inject(). Analogía: un enchufe en la pared, no cada componente trae su generador.

carrito.service.ts
import { Injectable, signal } from '@angular/core';

@Injectable({ providedIn: 'root' })   // singleton en toda la app
export class CarritoService {
  private items = signal<Producto[]>([]);
  readonly cantidad = computed(() => this.items().length);

  agregar(p: Producto) {
    this.items.update(l => [...l, p]);
  }
}
export class HeaderComponent {
  carrito = inject(CarritoService);   // misma instancia que el catálogo
}

providedIn: 'root' = una instancia para toda la app. Un servicio también puede ir en providers de un componente: entonces cada instancia de ese componente tiene la suya.

Datos y servicios

HttpClientprovideHttpClient()

Las llamadas al backend se hacen desde un servicio con HttpClient. Devuelve un Observable: nada pasa hasta que alguien se suscribe.

app.config.ts
// app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [provideHttpClient()],
};
@Injectable({ providedIn: 'root' })
export class ProductosService {
  private http = inject(HttpClient);
  private base = '/api/productos';

  listar()            { return this.http.get<Producto[]>(this.base); }
  obtener(id: number) { return this.http.get<Producto>(`${this.base}/${id}`); }
  crear(p: Producto)  { return this.http.post<Producto>(this.base, p); }
  borrar(id: number)  { return this.http.delete<void>(`${this.base}/${id}`); }
}
// en el componente: convertir el Observable en signal
productos = toSignal(this.api.listar(), { initialValue: [] });
Siempre tipá la respuesta (get<Producto[]>). Y nunca llames HTTP desde el template ni desde el constructor.

Datos y servicios

RxJS esencialObservable · pipe

Un Observable es un flujo de valores en el tiempo (una respuesta HTTP, los clicks, lo que escribe el usuario). Se transforma con operadores dentro de pipe(). Analogía: una cinta transportadora donde cada operador es una estación.

import { map, filter, switchMap, debounceTime } from 'rxjs';

// buscador: espera que deje de tipear y pide al server
this.busqueda.valueChanges.pipe(
  debounceTime(300),
  filter(t => t.length >= 3),
  switchMap(t => this.api.buscar(t)),   // cancela la anterior
).subscribe(res => this.resultados.set(res));
OperadorQué hace
map(x => ...)Transforma cada valor
filter(x => cond)Deja pasar solo algunos
switchMap(x => obs)Cambia a otro flujo y cancela el anterior (ideal para HTTP)
debounceTime(ms)Espera una pausa antes de emitir
catchError(e => of([]))Maneja errores sin romper el flujo
toSignal(obs)Puente a signals: se suscribe y desuscribe solo
Regla: si te suscribís a mano, desuscribite en ngOnDestroy o usá takeUntilDestroyed(). Con toSignal no hace falta.

Formularios

Formularios reactivosFormGroup · FormControl

El formulario se define en la clase (no en el HTML): cada campo es un FormControl con validadores, agrupados en un FormGroup. El template solo se conecta.

import { FormBuilder, Validators, ReactiveFormsModule } from '@angular/forms';

@Component({ imports: [ReactiveFormsModule], ... })
export class LoginComponent {
  private fb = inject(FormBuilder);

  form = this.fb.nonNullable.group({
    email:    ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(8)]],
  });

  enviar() {
    if (this.form.invalid) { this.form.markAllAsTouched(); return; }
    const { email, password } = this.form.getRawValue();
    this.auth.login(email, password).subscribe();
  }
}
<form [formGroup]="form" (ngSubmit)="enviar()">
  <input formControlName="email" type="email">
  @if (form.controls.email.hasError('required')
       && form.controls.email.touched) {
    <small>El email es obligatorio</small>
  }
  <input formControlName="password" type="password">
  <button [disabled]="form.invalid">Ingresar</button>
</form>
EstadoSignifica
valid / invalidPasa o no todas las validaciones
touchedEl usuario entró y salió del campo
dirtyEl valor cambió
value / getRawValue()Valor actual (raw incluye deshabilitados)

Signal Forms (@angular/forms/signals) es la API nueva, todavía experimental. Aprendé primero esta, que es la que vas a encontrar en los proyectos.

Zoneless y detección de cambiosprovideZonelessChangeDetection

Angular clásico usaba zone.js para enterarse de que algo cambió (parchea setTimeout, eventos, fetch). Con signals ya no hace falta: la vista sabe exactamente qué leer y cuándo se actualizó. Sin zone la app es más liviana y predecible.

// app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [provideZonelessChangeDetection()],
};
Con zone.jsZoneless
Cualquier propiedad cambia la vista (mágico pero caro)Solo signals, inputs y eventos del template refrescan
ChangeDetectionStrategy.OnPush como optimizaciónOnPush pasa a ser lo normal
cdr.detectChanges() para forzarNo se fuerza: si no se refresca, falta un signal
setTimeout(() => this.x = 1) refrescasetTimeout(() => this.x.set(1)) es lo que refresca
Diagnóstico: si una vista no se actualiza en zoneless, el dato está en una propiedad plana. Convertila en signal.

Directivas personalizadas@Directive · host

Una directiva agrega comportamiento a un elemento existente sin crear un componente nuevo. Analogía: un adhesivo que le pega una habilidad a cualquier etiqueta.

@Directive({
  selector: '[appResaltar]',
  host: {
    '[style.background]': 'activo() ? color() : null',
    '(mouseenter)': 'activo.set(true)',
    '(mouseleave)': 'activo.set(false)',
  },
})
export class ResaltarDirective {
  color = input('#fde68a', { alias: 'appResaltar' });
  activo = signal(false);
}
<p appResaltar="#fbcfe8">Pasá el mouse</p>

El objeto host reemplaza a @HostBinding y @HostListener. Lo mismo aplica a componentes: estilos y eventos del elemento raíz van ahí.

Arquitectura

Pipes personalizados@Pipe · transform

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({ name: 'pesos' })
export class PesosPipe implements PipeTransform {
  transform(valor: number, decimales = 0): string {
    return '$ ' + valor.toLocaleString('es-AR', {
      minimumFractionDigits: decimales,
      maximumFractionDigits: decimales,
    });
  }
}
<p>{{ producto.precio | pesos }}</p>       <!-- $ 3.500 -->
<p>{{ producto.precio | pesos:2 }}</p>     <!-- $ 3.500,00 -->

Un pipe es puro por defecto: solo se recalcula si cambia el valor de entrada. Perfecto para formateo; nunca para lógica con efectos.

Datos y servicios

Interceptors y guardsHttpInterceptorFn · CanActivateFn

Un interceptor se mete en cada request/response HTTP (token, errores, loading). Un guard decide si se puede entrar a una ruta. Ambos son funciones.

auth.interceptor.ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).token();
  const conToken = token
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })
    : req;
  return next(conToken).pipe(
    catchError(err => {
      if (err.status === 401) inject(Router).navigate(['/login']);
      return throwError(() => err);
    }),
  );
};
// app.config.ts
provideHttpClient(withInterceptors([authInterceptor]))
auth.guard.ts
export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  return auth.logueado() ? true : inject(Router).createUrlTree(['/login']);
};

Organizá por funcionalidad, no por tipo de archivo. Cada feature tiene sus componentes, servicio y rutas; lo compartido va a shared/ y lo que vive una sola vez (auth, layout) a core/.

estructura

// estado compartido: servicio + signals (sin librerías)
@Injectable({ providedIn: 'root' })
export class PedidosStore {
  private _pedidos = signal<Pedido[]>([]);
  readonly pedidos = this._pedidos.asReadonly();
  readonly pendientes = computed(() =>
    this._pedidos().filter(p => p.estado === 'pendiente'));

  cargar() { this.api.listar().subscribe(l => this._pedidos.set(l)); }
}

Migración automáticang g @angular/core:…

La CLI trae schematics que convierten el código viejo. Se corren una vez por proyecto y dejan el resultado listo para revisar en el diff.

ComandoQué migra
ng g @angular/core:standaloneElimina NgModules y pasa a standalone
ng g @angular/core:control-flow*ngIf / *ngFor / ngSwitch → bloques @
ng g @angular/core:injectConstructor DI → inject()
ng g @angular/core:signal-inputs@Input() → input()
ng g @angular/core:outputs@Output() → output()
ng g @angular/core:signal-queries@ViewChild → viewChild()
ng update @angular/core @angular/cliSube de versión mayor con migraciones incluidas
Orden sugerido: standalone → control-flow → inject → signal-inputs / outputs / queries. Un commit por paso, tests verdes entre medio.
